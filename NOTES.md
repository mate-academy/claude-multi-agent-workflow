# Code Quality & Testing Plugin - Design Notes

## Overview

The **code-quality-workflow** plugin bundles two specialized subagents that work together to improve code quality through automated review and comprehensive test generation. The plugin addresses a common developer workflow: understanding code issues and ensuring those issues are properly tested.

## Installation

### From Marketplace

First, add the marketplace to your Claude Code instance:

```bash
/plugin marketplace add https://github.com/imphanpagnarith/claude-multi-agent-workflow
```

Then install the plugin:

```bash
/plugin install code-quality-workflow@<your-marketplace-name>
```

### Local Development

To test locally during development:

```bash
cd /path/to/this/repo
claude --plugin-dir .
/reload-plugins
```

Then run the workflow:

```bash
/review-and-test path/to/file.js
```

## Plugin Components

### Agents

**code-reviewer** (Opus 4.8)
- **Purpose:** Analyzes code for bugs, anti-patterns, and quality issues
- **Tools:** Read, Bash (read-only focused)
- **Scoping Decision:** Intentionally limited to read-only tools because the reviewer's job is analysis, not modification. This prevents accidental changes and ensures the agent stays focused on its single responsibility—identifying problems.
- **Model Choice:** Opus 4.8 for deep analysis of complex code patterns and subtle bugs

**test-generator** (Opus 4.8)
- **Purpose:** Generates comprehensive test cases based on code structure
- **Tools:** Read, Write, Edit, Bash (can create and modify files)
- **Scoping Decision:** Includes Write and Edit because test generation requires file creation. The agent writes new `.test.js` files and may edit them during refinement. By including these tools only in this agent, we ensure test files are generated intentionally and separately from review feedback.
- **Model Choice:** Opus 4.8 for understanding code paths and generating meaningful test scenarios

### Commands

**/review-and-test**
- Orchestrates both agents into a unified workflow
- Trigger: `/review-and-test path/to/file.js`

### Skills

**code-analyzer**
- Provides complexity metrics and code health scoring
- Helps identify which parts of code need priority testing
- Complementary to the agents but invoked independently

### Hooks

**check-code-quality.sh**
- Runs on file-written events for .js, .ts, .jsx, .tsx files
- Provides quick feedback about common issues (console.log, commented code, etc.)
- Uses `${CLAUDE_PLUGIN_ROOT}` for portable path resolution

## Workflow Orchestration

### Why Parallel Review & Test Generation?

The workflow runs the code-reviewer and test-generator agents **in parallel** during Step 1 because:

1. **Independence** — The agents don't depend on each other's output to start work. Both can begin analyzing the code file immediately.
2. **Efficiency** — Running them simultaneously cuts total execution time in half compared to sequential execution.
3. **Different perspectives** — The reviewer finds problems; the generator identifies code paths. These perspectives inform each other but don't block each other.

Example: A 30-second review + 30-second test generation takes 30 seconds total in parallel, vs 60 seconds sequentially.

### Why Sequential Synthesis?

Step 2 (synthesis) **depends on Step 1** because:

1. **Requires both inputs** — The synthesis step must wait for both agents to complete to create a unified report that connects:
   - Issues found by the reviewer
   - Test cases generated by the test-generator
   - A recommended test strategy that prioritizes critical issues

2. **Prevents incomplete insights** — Without both reviews, the synthesis would be incomplete or misleading.

**Orchestration Example:**
```
Start
├─ [Parallel] Run code-reviewer    ──┐
└─ [Parallel] Run test-generator   ──┤
                                    ──┼─ [Sequential] Synthesize findings
                                      │
                                      └─ Output unified report
```

## Design Decisions Summary

| Decision | Rationale |
|----------|-----------|
| Two agents instead of one | Separation of concerns: review (analysis) vs test generation (creation) |
| code-reviewer is read-only | Prevents accidental changes; keeps focus narrow |
| test-generator can write | Tests are new files, not modifications to source code |
| Parallel review + test gen | Independent tasks that run faster together |
| Sequential synthesis step | Requires both outputs for meaningful correlation |
| Opus 4.8 for both agents | Code analysis and test generation are complex tasks requiring strong reasoning |
| Skill separate from agents | Metrics can be run independently before/after workflow |
| File-written hook | Provides continuous feedback during development without explicit invocation |

## Troubleshooting

**Plugin doesn't load?**
- Check folder structure: `.claude-plugin/plugin.json` must be in `.claude-plugin/`, not at root
- Verify all `.md` files have valid YAML frontmatter
- Run `/reload-plugins` to pick up changes

**Agents don't run in the right order?**
- Ensure workflow command has correct agent names (must match agent `.md` filename prefixes)
- Check that dependent steps correctly reference earlier step outputs

**Marketplace installation fails?**
- Verify `marketplace.json` lists the same plugin name as `plugin.json`
- Confirm `source: "./"` points to this repo root
